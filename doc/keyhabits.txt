*keyhabits.txt*  Record your key habits and report them

keyhabits records every key you press, with the mode you pressed it in, and
reports the keys and commands you repeat most. It is written in Lua for
Neovim and LazyVim.

INTRODUCTION                                        *keyhabits-introduction*

keyhabits watches every physical key press through |vim.on_key()| and groups
the keys into commands: a command starts in Normal mode and ends when you
return to Normal, so "ciw", the text you type and the closing <Esc> are one
command, and plain motions such as "j" are one command each. The log is a
plain JSONL file, and the report counts what is in it.

Keys that plugins such as which-key or mini.ai read and then feed back are
counted once, as you typed them.

Requires Neovim 0.11 or newer. The Vim 9 version is on the `legacy-vim9`
branch of the repository.

==============================================================================
SETUP                                                      *keyhabits-setup*

With LazyVim, add a plugin spec: >lua

    return {
      "amphetamarina/keyhabits",
      event = "VeryLazy",
      opts = {},
      keys = {
        { "<leader>uK", "<cmd>KeyHabits report<cr>", desc = "Key Habits Report" },
      },
    }
<
lazy.nvim calls `require("keyhabits").setup(opts)`, which starts recording.
Without lazy.nvim, put the plugin on 'runtimepath' and call setup() yourself.

==============================================================================
COMMANDS                                                *keyhabits-commands*

:KeyHabits [report] [{days}]                                    *:KeyHabits*
        Open the report in a float. With {days}, only the last {days} days.
        See |keyhabits-report|.

:KeyHabits start                                        *:KeyHabits-start*
:KeyHabits stop                                         *:KeyHabits-stop*
        Start or stop recording. Stopping writes what is buffered.

:KeyHabits[!] clear                                     *:KeyHabits-clear*
        Stop recording and delete the log after a confirmation. With [!]
        the question is skipped.

`:checkhealth keyhabits` reports whether recording runs and where the log
is.

The same are available from Lua: `require("keyhabits")` has setup(),
start(), stop(), report(days), clear(force), is_recording() and log_file().

==============================================================================
OPTIONS                                                  *keyhabits-options*

Passed to setup(), shown here with their defaults: >lua

    {
      log_file = "$XDG_DATA_HOME/keyhabits/events.jsonl",
      auto_start = true,
      flush_threshold = 200,
      flush_interval = 30000,
      record_text = false,
      report = { limit = 20 },
    }
<
log_file          Where events are appended. Without $XDG_DATA_HOME,
                  "~/.local/share/keyhabits/events.jsonl".
auto_start        Start recording when setup() runs.
flush_threshold   Events buffered before they are written.
flush_interval    Milliseconds between writes of a partial buffer; 0 turns
                  the timer off.
record_text       Store typed text instead of <text>. See |keyhabits-privacy|.
report.limit      Entries shown per ranked section of the report.

==============================================================================
REPORT                                                    *keyhabits-report*

`:KeyHabits` opens a float with these sections; q closes it.

Top keys        The keys you physically typed, most frequent first. Text
                typed in a text mode counts as <text>, one per character.
Top commands    The commands you repeated, most frequent first. Typed text
                inside a command counts as one <text>, and groups that do not
                start in Normal or Visual mode are left out, so plain typing
                never shows up here.
Top key pairs   Keys that follow each other, counted within a session.
Modes           How often each mode was active, as Normal, Insert, Visual,
                Command-line, Replace or Terminal.
Filetypes       The 'filetype' of the buffer each key was pressed in.

==============================================================================
PRIVACY                                                  *keyhabits-privacy*

In Insert, Replace, Command-line and Terminal modes the printable characters
are the text you are entering, which can include passwords. By default each is
stored as the placeholder <text>, so counts and rhythm survive while the
content does not. Special keys such as <Esc>, <C-w>, <CR>, <Tab> and the arrow
keys are stored as they are. Keys that mappings or Neovim generate are not
stored.

WARNING: with `record_text = true` the log contains everything you type,
including passwords, in clear text.

==============================================================================
LOG FORMAT                                            *keyhabits-log-format*

One JSON object per line, appended in batches, so at most `flush_threshold`
events are lost by a crash. The format is shared with the Vim 9 version:

        ts      number  seconds since the epoch when the key was seen
        sid     string  session id, "<pid>-<start time>"
        grp     number  command group; events sharing (sid, grp) were typed
                        as one command
        mode    string  the mode when the key was pressed
        key     string  the key after mappings
        typed   string  the key you physically typed
        ft      string  filetype of the buffer

A line that cannot be read back is skipped and counted; the report then warns
with "keyhabits: skipped N unreadable lines".
