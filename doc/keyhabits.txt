*keyhabits.txt*  Record your key habits and get tips for better commands

keyhabits records every key you press, with the mode you pressed it in,
reports the keys and commands you repeat most, and tells you the moment a
habit has a better command. It is written in Lua for Neovim and LazyVim.

INTRODUCTION                                        *keyhabits-introduction*

keyhabits watches every physical key press through |vim.on_key()| and groups
the keys into commands: a command starts in Normal mode and ends when you
return to Normal, so "ciw", the text you type and the closing <Esc> are one
command, and plain motions such as "j" are one command each. From those it
builds a report, and it matches them against a catalogue of tips while you
work.

Requires Neovim 0.11 or newer. The Vim 9 version is on the `legacy-vim9`
branch of the repository.

==============================================================================
SETUP                                                      *keyhabits-setup*

With LazyVim, add a plugin spec: >lua

    return {
      "amphetamarina/keyhabits",
      event = "VeryLazy",
      opts = {},
    }
<
lazy.nvim calls `require("keyhabits").setup(opts)`, which starts recording.
Without lazy.nvim, put the plugin on 'runtimepath' and call setup() yourself.

The README shows how to add a Snacks toggle on <leader>uk and a
report key.

==============================================================================
COMMANDS                                                *keyhabits-commands*

:KeyHabits [report] [{days}]                                    *:KeyHabits*
        Open the report in a float. With {days}, only the last {days} days.
        See |keyhabits-report|.

:KeyHabits start                                        *:KeyHabits-start*
:KeyHabits stop                                         *:KeyHabits-stop*
        Start or stop recording. Stopping writes what is buffered.

:KeyHabits toggle                                      *:KeyHabits-toggle*
        Turn live tips on or off. Recording goes on either way.

:KeyHabits why                                            *:KeyHabits-why*
        Open the help for the last tip shown.

:KeyHabits tips                                          *:KeyHabits-tips*
        List the tips active in this editor, and the ones left out with the
        reason: switched off in setup(), a plugin missing, or a key mapped
        to something else.

:KeyHabits[!] clear                                     *:KeyHabits-clear*
        Stop recording and delete the log after a confirmation. With [!]
        the question is skipped.

`:checkhealth keyhabits` reports whether recording runs, where the log is
and which tips are left out.

The same are available from Lua: `require("keyhabits")` has setup(),
start(), stop(), report(days), toggle_tips(), set_tips(on), tips_enabled(),
why(), last_tip(), catalogue(), clear(force), is_recording() and log_file().

==============================================================================
OPTIONS                                                  *keyhabits-options*

Passed to setup(), shown here with their defaults: >lua

    {
      log_file = "$XDG_DATA_HOME/keyhabits/events.jsonl",
      auto_start = true,
      flush_threshold = 200,
      flush_interval = 30000,
      record_text = false,
      report = { limit = 20 },
      tips = {
        enabled = true,
        threshold = 1,
        window = 60,
        cooldown = 600,
        disable = {},
      },
    }
<
log_file          Where events are appended. Without $XDG_DATA_HOME,
                  "~/.local/share/keyhabits/events.jsonl".
auto_start        Start recording when setup() runs.
flush_threshold   Events buffered before they are written.
flush_interval    Milliseconds between writes of a partial buffer; 0 turns
                  the timer off.
record_text       Store typed text instead of <text>. See |keyhabits-privacy|.
report.limit      Entries shown per ranked section of the report.
tips.enabled      Show tips while you work.
tips.threshold    How many times one habit must occur within the window
                  before its tip shows. A run such as "jjjjjjjj" counts once.
tips.window       Seconds of recent commands watched.
tips.cooldown     Seconds before the same tip may show again.
tips.disable      Tip ids never to show; `:KeyHabits tips` lists the ids.

==============================================================================
TIPS                                                        *keyhabits-tips*

A tip shows as a notification through |vim.notify()|, which LazyVim draws
with noice or snacks. It names the better command and the help it comes from;
`:KeyHabits why` opens that help. Every tip is backed by the help that ships
with Neovim, or with the plugin it needs, and the better way does the same
thing as the habit it replaces.

The tips know the editor they run in:

- A tip whose suggested key your config maps to something else is not shown.
  In LazyVim "s" is flash.nvim and "H" is the previous buffer, so tips that
  suggest them stay quiet. A mapping counts as "something else" when it has
  a description and does not simply run the key itself.
- When flash.nvim is installed, tips for long runs of motions suggest its
  jumps instead.
- Tips that rely on a mapping show only when it exists, and say where it
  comes from: LazyVim's CTRL-J for "CTRL-W j" and Alt-j for "ddp", or
  Neovim's own ]<Space> for "o<Esc>k".
- Tips that need a plugin, such as mini.ai's search for the next pair, show
  only when it is installed.

A macro being recorded or replayed is never coached.

==============================================================================
REPORT                                                    *keyhabits-report*

`:KeyHabits` opens a float with these sections. <CR> on a tip opens its
help; q closes the float.

Advice          Habits a better command would replace, ranked by the keys
                it would have saved, each with its help topic. Runs never
                span two sessions.
Repeated, no tip yet
                Commands repeated three or more times in a row that no tip
                covers. A command line run again (":<text><CR>") stays here:
                its text is not recorded, so a repeat cannot be told apart
                from a different command.
Top keys        The keys you physically typed, most frequent first.
Top commands    The commands you repeated, most frequent first.
Top key pairs   Keys that follow each other, counted within a session.
Modes           How often each mode was active, as Normal, Insert, Visual,
                Command-line, Replace or Terminal.
Filetypes       The 'filetype' of the buffer each key was pressed in.

==============================================================================
PRIVACY                                                  *keyhabits-privacy*

In Insert, Replace, Command-line and Terminal modes the printable characters
are the text you are entering, which can include passwords. By default each is
stored as the placeholder <text>, so counts and rhythm survive while the
content does not. Special keys such as <Esc>, <C-w>, <CR>, <Tab> and the arrow
keys are stored as they are. Keys that mappings or Neovim generate are not
stored.

WARNING: with `record_text = true` the log contains everything you type,
including passwords, in clear text.

==============================================================================
LOG FORMAT                                            *keyhabits-log-format*

One JSON object per line, appended in batches, so at most `flush_threshold`
events are lost by a crash. The format is shared with the Vim 9 version:

        ts      number  seconds since the epoch when the key was seen
        sid     string  session id, "<pid>-<start time>"
        grp     number  command group; events sharing (sid, grp) were typed
                        as one command
        mode    string  the mode when the key was pressed
        key     string  the key after mappings
        typed   string  the key you physically typed
        ft      string  filetype of the buffer

A line that cannot be read back is skipped and counted; the report then warns
with "keyhabits: skipped N unreadable lines".
